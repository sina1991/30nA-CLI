# Port Management Agent

ایجنت عمومی -port مستقل از تخصیص‌دهنده داخلی Port Worker است. با ss از iproute2، Socketهای محلی را در Network Namespace جاری مشاهده می‌کند. حالت‌های مشاهده هیچ Socket یا سرویس را متوقف نمی‌کنند. آزادسازی اضطراری فقط با -force و مالک صریح انجام می‌شود.

```bash
clear
30na -port -list
30na -port -all
30na -port -list -tcp
30na -port -list -udp
30na -port -summary
30na -port -check 5555
30na -port -check 443 -tcp
```

-list شامل Listenerهای TCP و UDP بدون اتصال است؛ -all شامل سایر وضعیت‌های Socket نیز می‌شود. -check همه وضعیت‌های محلی را برای یک شماره پورت بررسی می‌کند. نبودن رکورد، تضمین امکان Bind نیست. مالک و PID از ss و نام Unit سرویس از cgroup همان PID در صورت دسترسی استخراج می‌شود؛ ? به معنی نامعلوم یا عدم دسترسی است. شمارنده T/U در Status Bar تعداد شماره پورت‌های متمایز TCP/UDP در -list است، نه تعداد Socket یا سرویس. مشاهده Snapshot با Refresh به‌روز می‌شود؛ تغییر Tunnel یا Systemd مقدار شمارنده را نامعلوم می‌کند. برای توقف سرویس شناخته‌شده از Agent سرویس‌ها و تأیید صریح استفاده کنید. دسترسی root برای دیدن مالک بعضی Socketها ضروری است؛ ابزار به‌صورت خودکار sudo اجرا نمی‌کند. مالک گزارش‌شده ممکن است در فاصله مشاهده تغییر کند.

## آزادسازی اضطراری

ابتدا -check را اجرا کنید. پروتکل و مالک دقیق را از خروجی انتخاب کنید. نام و PID زیر نمونه‌اند؛ بدون بررسی استفاده نکنید.

```bash
clear
30na -port -check 5555 -tcp
30na -port -force 5555 -tcp -unit example.service
30na -port -force 5555 -tcp -pid 12345
```

در -force تعیین TCP/UDP و دقیقاً یکی از -unit یا -pid الزامی است. برای سرویس system scope، مالکیت تمام Socketهای منتخب در cgroup همان Unit بررسی و از Service Agent برای Stop استفاده می‌شود. برای فرایند مستقل، Linux pidfd هویت فرایند را تثبیت می‌کند؛ ابتدا SIGTERM و در صورت باقی ماندن مالکیت تأییدشده پس از فرصت کوتاه SIGKILL ارسال می‌شود. PID مشترک، نامعلوم، تغییر مالکیت، Unit غیرقابل تأیید، فرایند تحت مدیریت سرویس در حالت PID و فرایندهای محافظت‌شده SSH/Systemd/30nA رد می‌شوند. فرایند یا Unit ممکن است پورت‌ها یا وظایف دیگری هم داشته باشد؛ توقف می‌تواند سرویس را مختل کند. این محافظت‌ها همه سرویس‌های حیاتی را شناسایی نمی‌کنند. هیچ sudo خودکاری وجود ندارد. TUI تأیید صریح می‌خواهد. CLI با -force و مالک صریح دستور تغییر محسوب می‌شود. BEFORE/AFTER جزئیات Socket را نشان می‌دهند. RELEASED به معنی نبودن Listener یا UDP bound مشاهده‌شده در لحظه بررسی است، نه تضمین Bind، حذف TIME_WAIT یا جلوگیری از بازگشت Socket. در صورت باقی ماندن مالک، خروجی STILL_IN_USE و Exit 1 است. Socket activation یا Restart policy ممکن است پورت را دوباره اشغال کند. هیچ Unit به‌صورت خودکار Disable نمی‌شود.
