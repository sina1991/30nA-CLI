# Host Onboarding

از منوی Host یکی از دو گزینه Add / update host را انتخاب کنید: SSH onboarding برای کلید غیرتعاملی، یا password / key + password برای Prompt بومی OpenSSH. پس از تأیید، اتصال، نصب هماهنگ، بررسی و ثبت ID انجام می‌شوند. تکرار همان آدرس ID را حفظ می‌کند.

```bash
clear
30na -host -add -ip 192.0.2.10 -onboard
30na -host -add -ip 192.0.2.10 -onboard -password
30na -host -list -ids
```

کلیدهای موجود در HOME کاربر (برای root: /root/30na_windows و /root/30na_windows.pub) پس از بررسی مالکیت، مجوز فایل و تطابق واقعی با ssh-keygen، در ~/.ssh/30na-management/identity و identity.pub کپی می‌شوند. پوشه 0700 و فایل‌ها 0600 هستند. اصل فایل‌ها و کپی موجود تغییر نمی‌کنند. کلید خصوصی باید بدون Passphrase و با مجوز 0600 یا سخت‌گیرانه‌تر باشد؛ جفت‌کلید ناقص، نامعتبر، Symlink یا کلید خصوصی رمزگذاری‌شده پذیرفته نمی‌شود. کلید خصوصی به هیچ سرور یا مخزن ارسال نمی‌شود.

ابتدا ورود غیرتعاملی با کلید مدیریت و Host Key معتبر آزمایش می‌شود. -password اجازه Prompt بومی OpenSSH را در صورت شکست می‌دهد؛ هیچ مقدار رمزی به سوییچ داده نمی‌شود. پس از احراز هویت و کنترل Machine ID، ssh-copy-id فقط identity.pub را در حساب کاربر SSH مقصد ثبت می‌کند. ورود مجدد با همان کلید و بدون Password باید موفق باشد؛ اگر سرور همواره عامل دوم را الزام کند یا ثبت کلید مجاز نباشد، Host آماده ثبت نمی‌شود. کلید ناشناخته فقط با تأیید Fingerprint معتبر پذیرفته می‌شود و تغییر Host Key قبلی خودکار پذیرفته نمی‌شود. تنظیمات User/Port/HostName از SSH config حفظ می‌شوند؛ اگر IdentityFile یا CertificateFile دیگری در تنظیم مؤثر وجود داشته باشد، Onboarding برای جلوگیری از تأیید اشتباه کلید رد می‌شود. دستور Connect SSH نیز از کپی مدیریت موجود استفاده می‌کند. در صورت شکست پس از ssh-copy-id، کلید عمومی ممکن است در Remote باقی مانده باشد؛ حذف خودکار انجام نمی‌شود.

## نسخه و محدوده

- کنترل‌کننده باید از Git تمیز یا نصب دارای .revision اجرا شود. Remote باید Linux، Python، Git، دسترسی HTTPS به GitHub و پیش‌نیازهای نصب را داشته باشد. INSTALL_DEPS=0 است؛ نصب بسته‌های سیستم یا sudo خودکار انجام نمی‌شود.
- نسخه main گزارش می‌شود، اما فقط Commit دقیق کنترل‌کننده نصب می‌شود؛ ابتدا کنترل‌کننده را به آخرین main پذیرفته‌شده ارتقا دهید.
- شناسه ماشین مقایسه می‌شود تا خود سرور با نام مستعار نصب نشود؛ Host Key و این کنترل جایگزین ارزیابی کامل هویت سیستم نیستند.
- نصب در /usr/local برای root و ~/.local برای کاربر عادی است. هیچ shutdown، restart، stop یا تغییر Firewall انجام نمی‌شود. Worker قدیمی ممکن است به Restart برنامه‌ریزی‌شده نیاز داشته باشد.
- گزارش شامل OS، IP، اطلاعات سیستم، پورت‌های TCP/UDP و مالک، سرویس‌های فعال، Workerها و Forwardهای صریح -L/-R در argv فرایندهای SSH است. Forwardهای Config، ControlMaster و سمت sshd ممکن است قابل تشخیص نباشند. UNKNOWN یعنی بررسی کامل نبوده است. گزارش اثبات مسیر ترافیک یا سلامت مقصد نیست.
- گزارش در CLI/TUI نمایش داده می‌شود؛ پایگاه داده وضعیت Remote و اجرای متمرکز Tunnel هنوز پیاده‌سازی نشده است. ثبت پس از تأیید نصب انجام می‌شود. در صورت شکست ثبت پس از نصب یا timeout، وضعیت Remote را بررسی کنید.
- گزینه -add بدون -onboard همان ثبت آدرس آفلاین است؛ ثبت خودکار مقصد Tunnel به معنی نصب نیست.

در قرارداد شماره‌دار Forward، کلید مدیریت موجود به‌صورت خودکار استفاده می‌شود؛ نیازی به افزودن IdentityFile دستی نیست. Supervisor قدیمی باید در زمان مناسب و پس از بررسی Tunnelهای فعال به نسخه جدید منتقل شود؛ نصب خودکار آن را متوقف نمی‌کند.
