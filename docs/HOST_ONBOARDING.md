# Host Onboarding

از منوی Host یکی از دو گزینه Add / update host را انتخاب کنید: SSH onboarding برای کلید غیرتعاملی، یا password / key + password برای Prompt بومی OpenSSH. پس از تأیید، اتصال، نصب هماهنگ، بررسی و ثبت ID انجام می‌شوند. تکرار همان آدرس ID را حفظ می‌کند.

```bash
clear
30na -host -add -ip 192.0.2.10 -onboard
30na -host -add -ip 192.0.2.10 -onboard -password
30na -host -list -ids
```

گزینه -password هیچ مقدار رمزی نمی‌گیرد. در ترمینال تعاملی OpenSSH ابتدا روش publickey و سپس password/keyboard-interactive را طبق سیاست سرور پیشنهاد می‌دهد؛ در صورت نیاز Passphrase کلید یا عامل دوم نیز درخواست می‌شود. احراز هویت دو عاملی فقط اگر سرور آن را الزامی کند انجام می‌شود. هیچ رمزی ذخیره یا منتقل به آرگومان نمی‌شود. در حالت غیرتعاملی فقط publickey و Host Key از قبل تأییدشده پذیرفته می‌شود. در حالت تعاملی برای Host ناشناخته، Fingerprint را از کانال معتبر مستقل بررسی کنید؛ تغییر کلید قبلی را خودکار نپذیرید. User، Port، IdentityFile و سایر تنظیمات از SSH config خوانده می‌شوند. برای مدیریت غیرتعاملی بعدی باید کلید و مجوز مناسب از قبل فراهم باشد؛ ورود با Password به‌تنهایی دسترسی دائمی ایجاد نمی‌کند. کلید یا مجوز جدید خودکار نصب نمی‌شود.

## نسخه و محدوده

- کنترل‌کننده باید از Git تمیز یا نصب دارای .revision اجرا شود. Remote باید Linux، Python، Git، دسترسی HTTPS به GitHub و پیش‌نیازهای نصب را داشته باشد. INSTALL_DEPS=0 است؛ نصب بسته‌های سیستم یا sudo خودکار انجام نمی‌شود.
- نسخه main گزارش می‌شود، اما فقط Commit دقیق کنترل‌کننده نصب می‌شود؛ ابتدا کنترل‌کننده را به آخرین main پذیرفته‌شده ارتقا دهید.
- شناسه ماشین مقایسه می‌شود تا خود سرور با نام مستعار نصب نشود؛ Host Key و این کنترل جایگزین ارزیابی کامل هویت سیستم نیستند.
- نصب در /usr/local برای root و ~/.local برای کاربر عادی است. هیچ shutdown، restart، stop یا تغییر Firewall انجام نمی‌شود. Worker قدیمی ممکن است به Restart برنامه‌ریزی‌شده نیاز داشته باشد.
- گزارش شامل OS، IP، اطلاعات سیستم، پورت‌های TCP/UDP و مالک، سرویس‌های فعال، Workerها و Forwardهای صریح -L/-R در argv فرایندهای SSH است. Forwardهای Config، ControlMaster و سمت sshd ممکن است قابل تشخیص نباشند. UNKNOWN یعنی بررسی کامل نبوده است. گزارش اثبات مسیر ترافیک یا سلامت مقصد نیست.
- گزارش در CLI/TUI نمایش داده می‌شود؛ پایگاه داده وضعیت Remote و اجرای متمرکز Tunnel هنوز پیاده‌سازی نشده است. ثبت پس از تأیید نصب انجام می‌شود. در صورت شکست ثبت پس از نصب یا timeout، وضعیت Remote را بررسی کنید.
- گزینه -add بدون -onboard همان ثبت آدرس آفلاین است؛ ثبت خودکار مقصد Tunnel به معنی نصب نیست.
