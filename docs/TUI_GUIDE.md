# مرکز کنترل 30nA — TUI

برای باز کردن منوی اصلی در Termius یا ترمینال Linux:

```bash
clear
30na -menu -tui
```

منو با curses و بدون نیاز به Desktop اجرا می‌شود. رابط انگلیسی است تا نمایش RTL در ترمینال‌های مختلف مشکل ایجاد نکند. در عرض کم، Status Bar فشرده می‌شود. حداقل اندازه ۲۴ ستون و ۸ سطر است؛ برای دیدن فرم و پیش‌نمایش فرمان، ترمینال بزرگ‌تر مناسب است.

## منوها

| گزینه | امکانات |
|---|---|
| Calculator | جمع، تفریق، ضرب، تقسیم و اجرای هر چهار عملیات |
| System | هر یک از ۷ فیلد سیستم یا همه فیلدها |
| Host | فهرست، ثبت IP/Domain، اتصال SSH، ثبت و اتصال، حذف |
| Tunnel | فهرست، Forward، Reverse با چهار فیلد Local/Remote، توقف و پاک کردن خطا |
| Files | مدیر فایل فعلی در مسیر جاری یا مسیر دلخواه |
| Help | راهنمای عمومی و راهنمای تمام Agentها |
| Services | مدیریت Systemd، فهرست سرویس‌ها، وضعیت Workerهای داخلی، Logs |

## کلیدها

- فلش بالا/پایین برای پیمایش، راست برای انتخاب یا اجرا، چپ برای بازگشت یا لغو؛ j/k، Enter و Esc نیز کار می‌کنند.
- Enter برای ورود، ویرایش فیلد یا اجرا روی RUN COMMAND؛ Enter دوباره مقدار را ذخیره می‌کند.
- هنگام ویرایش، Ctrl+U مقدار را پاک و Esc ویرایش را لغو می‌کند.
- f یا F2 روی تمام فیلدهای Tunnel و فیلد Unit سرویس، انتخاب‌گر را باز می‌کند. برای Local، ID 1 یا IP واقعی رابط شبکه؛ برای Remote، Host شماره‌دار یا IP/Domain دستی؛ برای پورت‌ها، پیشنهاد و مقدار دستی در دسترس است. پورت‌های پیشنهادی بررسی آزاد بودن نشده‌اند.
- r یا F5 در منوی اصلی، زیرمنوها و Overview اطلاعات System، Host، Tunnel، Systemd و Worker را دوباره می‌خواند؛ فهرست Host/Tunnel ممکن است Worker لازم را راه‌اندازی کند. هنگام ورود اولیه، فهرست Workerهای متوقف به‌صورت خودکار راه‌اندازی نمی‌شود.
- ایجاد Tunnel، حذف Host، توقف Tunnel و تغییر وضعیت Systemd نیازمند تأیید y است؛ n یا Esc لغو می‌کند.
- در صفحه خروجی، فلش‌ها و PgUp/PgDn برای اسکرول، Esc برای بازگشت و q برای خروج‌اند.
- اتصال SSH تعاملی ترمینال را موقتاً از curses خارج می‌کند و پس از پایان اتصال، به منو بازمی‌گردد.

## Status Bar

در ترمینال رنگی، READY با Cyan، RUNNING با زرد، OK با سبز و ERROR با قرمز متمایز می‌شوند؛ در ترمینال بدون رنگ، متن وضعیت همچنان نمایش داده می‌شود. سه مفهوم جداگانه نمایش داده می‌شوند: وضعیت اجرای فرمان (READY/RUNNING/OK/ERROR و Exit Code)، تعداد Hostها و Tunnelهای ready/starting/failed در آخرین مشاهده، و راهنمای کلیدها. علامت ? یعنی مقدار نامعلوم؛ صفر تنها پس از مشاهده واقعی نمایش داده می‌شود. شمارنده‌ها Snapshot هستند نه مانیتور لحظه‌ای. در عرض کافی، زمان مشاهده هر فهرست نیز نشان داده می‌شود. بعد از تغییر یک Agent، شمارنده مربوطه نامعلوم می‌شود تا دوباره Refresh کنید. موفق بودن فرمان List به معنی موفق بودن همه Tunnelها نیست.

## سازگاری و محدودیت

دستورات CLI قبلی و سیاست Loopback آن‌ها، Host authorization و بازیابی اختیاری حفظ می‌شوند. قرارداد جدید Local/Remote در Forward فقط با IP محلی صریح می‌تواند روی همان رابط Bind کند. Dashboard فرمان‌ها را با آرگومان مجزا، بدون Shell و با Launcher همان Release اجرا می‌کند. اجرای غیرتعاملی هر فرمان حداکثر ۱۵ ثانیه فرصت دارد؛ Timeout لزوماً به معنی لغو عملیات Worker نیست. خروجی هر Stream تا ۶۴ KiB نمایش داده می‌شود. فرمان SSH تعاملی تا زمان خروج کاربر ادامه دارد. انتخاب Remote ID نیاز به ثبت قبلی دارد؛ آدرس صریح Remote در صورت نیاز ثبت می‌شود و تنظیم User/Key/Port طبق OpenSSH است.

مدیر فایل مستقیم و رابط شماره‌ای قبلی همچنان قابل استفاده‌اند:

```bash
clear
30na -menu -dir /var -tui
30na -menu -text
```

در SSH تعاملی بدون DISPLAY، حالت GUI بدون مسیر نیز به مرکز کنترل TUI برمی‌گردد. GUI با DISPLAY و منوی شماره‌ای همچنان همان رفتار قبلی را دارند.

## چیدمان چندپنلی

در ابعاد ۱۰۰ ستون و ۱۹ سطر به بالا، Header دو بخش System و Context Help دارد؛ سمت چپ فهرست Agentها، وسط امکانات و فرم، و سمت راست وضعیت مشاهده‌شده است. راهنما با تغییر انتخاب Agent یا فیلد تغییر می‌کند. کلیدهای [ و ] پنل وضعیت را اسکرول می‌کنند. در ترمینال باریک، چیدمان فشرده می‌شود و v صفحه Overview کامل را باز می‌کند. وضعیت‌ها Snapshot هستند و هیچ مقدار نامعلوم به‌عنوان صفر نمایش داده نمی‌شود. برای فهرست کامل سرویس‌ها و Tunnelها از منوهای مربوطه استفاده کنید. Worker port با reported یعنی PID گزارش‌شده از Supervisor، نه بررسی مستقل زنده بودن. Calculator/System و سایر Agentهای یک‌بار اجراشونده Worker دائمی نیستند.

در خطای host_key_failed، راهنمای تأیید Fingerprint و اتصال مستقیم SSH در صفحه خروجی نمایش داده می‌شود. هیچ کلید اعتماد SSH به‌صورت خودکار حذف یا پذیرفته نمی‌شود.

## IP خود سرور

System Agent با گزینه -ip آدرس‌های Interface محلی را از hostname -I می‌خواند، بدون DNS یا ثبت Host. Header و Overview این آدرس‌ها را نشان می‌دهند. در Local Host، کلید f همین IPها و انتخاب پیش‌فرض ID 1 را ارائه می‌کند. در Forward، مقصد از سمت سرور SSH قابل دسترسی است؛ در Reverse، مقصد از سمت سرور محلی. IP مشاهده‌شده ممکن است خصوصی یا پشت NAT باشد و الزاماً Public IP نیست. آدرس صریح Remote در صورت نیاز ثبت می‌شود.

## Ports

منوی 8 (Ports) فهرست TCP/UDP، همه Socketها، بررسی یک شماره و تعداد پورت‌ها را نمایش می‌دهد. Status Bar دارای Ports T/U (TCP/UDP) است و پنل وضعیت شماره و Unit مشاهده‌شده را نشان می‌دهد. [راهنمای Port Agent](PORT_AGENT_GUIDE.md).

منوی Ports دارای Emergency release by unit/PID است. ابتدا Inspect port number را اجرا کنید، سپس پروتکل و مالک دقیق را تعیین کنید. تأیید y برای عملیات توقف لازم است. خروجی BEFORE/AFTER و محدودیت‌ها در [Port Agent Guide](PORT_AGENT_GUIDE.md) آمده‌اند.

## رنگ و تمرکز بر برنامه

Local فیروزه‌ای، Remote ارغوانی؛ Tunnel Ready سبز، Starting زرد، Failed قرمز. متن نقش/وضعیت در ترمینال بدون رنگ نیز حفظ می‌شود. کلید h فهرست عمومی Systemd را Hide/Show می‌کند؛ پیش‌فرض مخفی است. Workerهای داخلی، Tunnelها، Hostها، و Unitهای فعال از تاریخچه Start/Restart همین Agent باقی می‌مانند. تاریخچه نشان‌دهنده مدیریت توسط برنامه است، نه مالکیت انحصاری یا اینکه Unit حتماً نخستین بار توسط برنامه راه‌اندازی شده است. فهرست Port همچنان مربوط به کل سیستم است. اطلاعات مشاهده‌شده با r تازه می‌شوند. فرم Tunnel چهار فیلد دارد و پیش‌نمایش CLI بدون Target نمایش داده می‌شود. Restore پیشرفته فقط در CLI اختیاری است.

پس از عملیات موفق Host/Tunnel/Service/Force، Snapshotهای مرتبط به‌صورت خودکار تازه می‌شوند. پورت‌های پیشنهادی مقدار فعلی را انتخاب‌شده نگه می‌دارند. پنل Tunnel جدید هر دو پورت را با F و R نمایش می‌دهد؛ جهت > برای Forward و < برای Reverse است.

## Host Onboarding

در Host، دو گزینه Add / update host برای Key و Password/Key+Password وجود دارد. گزینه دوم موقتاً curses را ترک می‌کند تا OpenSSH رمز را در Prompt بگیرد و سپس گزارش را در TUI نمایش دهد. Register address only ثبت آفلاین است. [راهنما](HOST_ONBOARDING.md).

در Onboarding، ابتدا کلیدهای مدیریت محلی بررسی می‌شوند؛ در گزینه Password، در صورت نیاز ssh-copy-id فقط کلید عمومی را ثبت می‌کند. [راهنما](HOST_ONBOARDING.md).
